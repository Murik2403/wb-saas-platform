## Доказательства и воспроизводимость

В операторской поставке `deliveries/audit-remediation-20261012/`:

- `offsite-owner-restore-20261012.json` — результат этой проверки без секретов
  и строк клиентских данных.
- `offsite_recipient_restore.py` — ограниченный read-only сценарий для этого
  конкретного существующего тестового объекта. Повторный запуск требует нового
  имени акта: предыдущий результат намеренно не перезаписывается.
- `crypto-acceptance-37720ffb9d4a4611aa3bd1d2f1379372.json` — исходный акт
  создания WBSAASBK2, проверки существующего WBSAASBK1 (16 SQLite), копирования
  единственного шифрованного объекта и download-check.

Свежие проверки кода: 14 тестов `test_backup_crypto.py` /
`test_backup_crypto_v2.py` из каталога `provisioner`, а также 16 тестов
`scripts/tests/test_backup_offsite_envelope.py` / `test_backup_offsite.py` из
корня проекта — все прошли. Неверный ключ/получатель, повреждение и обрезка
шифротекста не публикуют новый восстановленный файл. Начальная попытка общей
pytest-команды из корня не собрала provisioner-тесты из-за отсутствующего
`backup_crypto` в import path; запуск из предусмотренного каталога исправил
условия проверки без изменения исходников.

## Границы результата

Это реальное восстановление офсайт-копии контрольной базы, а не полная аварийная
пересборка инфраструктуры из S3. Все тома тенантов и шлюза ранее проверялись
отдельными актами candidate/rollback restore; их повторная загрузка из S3 в этой
проверке не выполнялась. Также не проверялось восстановление с другого компьютера
после утраты текущего устройства владельца или работоспособность независимой
второй копии его ключей.

Указанное наличие локального escrow подтверждает разделение сервера и ключа
получателя, но не заменяет независимое хранение ключей на случай утраты устройства.
Автоматическая ротация и удаление старых ключей этим результатом не разрешаются.

Дополнительная read-only сверка обнаружила отдельный операционный пробел:
`run_backup_cron.py` по умолчанию требует свежесть только групп
`control-plane,demo,mvvorokov,marketing`. В серверном `.env` и заданиях cron
переопределение `WB_SAAS_BACKUP_REQUIRED_GROUPS` не найдено. Новые действующие
тенанты `letoocean` и `alexdalex-msk` поэтому не входят в обязательный freshness
guard. Это не утверждение об отсутствии их архивов: исторические namespace
передаются отдельно. Требуется актуализация guard для полного текущего состава
тенантов; данный сценарий восстановления source/cron не менял.
