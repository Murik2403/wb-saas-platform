## Исправление и проверка исходников

`0bce83e` сохраняет дорогой расчёт вне writer lock. На той же SQLite connection
запоминается `PRAGMA data_version`; read transaction завершается, затем берётся
короткий `BEGIN IMMEDIATE`. Если внешняя запись изменила basis, расчёт повторяется.
Изменение версии от другой connection нельзя игнорировать. Повторы ограничены
32 попытками; непрерывная внешняя запись не возвращает выдуманный разрешающий
результат. Классификация, first_seen, cycles, себестоимость и WB-блокировка сохранены.

Регрессии используют настоящие WAL connections и HTTP ASGI: восемь запросов,
повтор одного наблюдения, внешняя запись между чтением и фиксацией, сохранение
исторического guard и безопасный отказ при постоянном изменении basis.
Старая реализация воспроизводит 500; новая проходит шесть регрессионных тестов.

Свежие полные проверки:

- tenant API до расширения request budget: **667 passed**;
- итоговый полный tenant API: **675 passed**;
- tenant app из рабочего каталога CI `tenant-app`: **1217 passed, 1 skipped**;
- scripts/standalone: **257 passed, 3 skipped**, 33 subtests;
- отдельный benchmark safety: **9 passed**, 17 subtests.

Первый запуск tenant app из корня проекта получил три ошибки subprocess imports
`db`/`sync_lock`; полный повтор из рабочего каталога CI прошёл. Это ошибка команды
проверки, а не скрытый успешный прогон. Process environment удалён из диагностики.

В `19ff0a1` отдельно закреплён локальный endpoint benchmark для Docker CLI и SDK.
Удалённые/неизвестные transports отклоняются; очистка требует собственного
префикса имени и точной метки запуска. Benchmark после этого не перезапускался;
старый отказ 20–30 кабинетов остаётся действительным результатом измерения.

## Выкладка

Первый immutable candidate `19ff0a16d5f270a32213aa188ccbc7db5dac3d83` не выложен:
demo прошёл 32 запроса (максимум 17,766 с), но восемь запросов на копии mvvorokov
превысили 35 с. Все исходные live identities сохранены; собственные серверные
копии удалены. Санитизированный отказ сохранён в первом операторском каталоге.

Причина дополнительного отказа: полный обзор контроля загружает большие
DataFrames, но маршрут отсутствовал в `DashboardWorkGuard`. Он также повторял
весь обзор для каждого одновременного GET. Теперь маршрут участвует в общей
очереди тяжёлых запросов; компактные диагностические строки/summary/reliability
используют штатный 20-секундный кэш с ключом settings/token-presence/sync/backup.
Успешная запись очищает кэш, изменение фоновой синхронизации меняет ключ.
Каждый ответ отдельно пересчитывает operational `fifo_guard`; разрешение операции
не берётся из кэша. Диагностическая FIFO-строка и балл могут отставать до 20 с
после сторонней записи — это не разрешение ручного списания.

90-дневные финансы, capacity, приватная Docker proxy сеть и 16 уроков.

Эта ограниченная регрессия не является нагрузочной приёмкой 20–30 кабинетов.
