## Исправления этого этапа

1. **PWA.** Действие обновления определяется в момент явного нажатия: активируется текущий ожидающий service worker, затем одна перезагрузка. Прежний порядок «баннер build-ID → новый SW» оставлял worker неактивированным и давал повторное предложение. Если worker уже активирован другой вкладкой, кнопка теперь перезагружает страницу, а не остаётся заблокированной без действия. До нажатия пользовательский ввод не сбрасывается. Незавершённая установка в момент нажатия не объявляется полностью покрытой.
2. **Возвраты ЮKassa.** В `get_refund` отсутствовал импорт `requests`; реальная проверка возврата могла дать NameError/500 до изменения БД. Исправлен импорт и сетевой отказ переведён в существующую ошибку проверки для повторной доставки webhook. Новые тесты подменяют HTTP transport, а не весь `get_refund`. Реальных возвратов/списаний при проверке нет; правила частичного возврата не менялись.
3. **Свежесть backups новых клиентов.** Подтверждён старый hardcoded список, пропускавший два новых кабинета. Обязательные группы теперь получаются из актуального реестра вместе с control-plane и явно настроенными группами. Отказ чтения реестра прекращает запуск с алертом вместо молчаливого неполного списка. Тенанты без уже созданного архива тоже проверяются; остановленные кабинеты с данными не исключаются.
4. **Офсайт-восстановление.** Реальный тестовый объект скачан из S3, расшифрованы внешний MHOFFSITE2 и внутренний WBSAASBK2 существующими owner-local ключами, SQLite integrity=ok. Детали и границы в `AUDIT_OFFSITE_RECOVERY_VERIFICATION_2026-10-12.md`.
