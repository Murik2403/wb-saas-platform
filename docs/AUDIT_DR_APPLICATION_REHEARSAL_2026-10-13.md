## Независимый реестр удалений

Реестр не взят из старого gateway-архива. Из `erasure-ledger-v1` скачаны **все**
immutable manifest/envelope пары (сейчас одна), аутентифицированы существующим
owner-local RSA-ключом и восстановлены как union. Его canonical SHA-256 сверён
с текущим живым реестром, прочитанным через read-only SQLite backup в память.
Совпадение подтверждает полноту выбранного union относительно текущей власти
реестра на момент чтения, а не только корректную расшифровку старого объекта.

Отдельный восстановленный SQLite монтируется в кандидата gateway с
`WB_SAAS_ERASURE_LEDGER_REQUIRED=1`. Живой реестр не заменяется. Текущая S3-пара
датирована 8 октября: snapshot дедуплицируется по неизменному содержимому,
поэтому дата объекта сама по себе не служит проверкой свежести.

Read-only проверка scheduler подтвердила `/etc/cron.d/wb-saas-pdn-backup`:
резервирование `*/15`, проверка свежести `7,22,37,52`, retention в 03:35 UTC.
Расписание не менялось и не запускалось этой репетицией.

## Изоляция и очистка

- `network=none`, ни опубликованных портов, ни Docker socket/живых data mounts.
- UID/GID 10001, memory 512 MiB, CPU 1, restart=no; кандидаты запускают только
  uvicorn, минуя entrypoint с background/Telegram worker. `MH_LOCAL_JOBS=0`,
  адрес внутренней доставки пуст; SMTP/Telegram/YooKassa/Sentry не настроены.
- Подпись шлюза синтетическая. Per-tenant encryption key из escrow передаётся
  через защищённый SSH stdin в память временного кандидата; в файл/вывод/Git
  не записывается. RSA private key и volume-backup key остаются на ПК владельца.
- Tar проходит preflight всех путей; запрещены traversal, ссылки, устройства,
  коллизии имён и превышение лимитов. Открытые данные только в выделенных
  owner-private временных папках, server UUID-каталогах с режимом 0700.
- После успешного полного запуска все **его** кандидаты и owner/server
  временные открытые копии удалены. Источники сохраняют исходные ID/образы и
  состояние running. Удаления известных/неизвестных архивов S3 не выполняются.

Во время ранних отладочных попыток осталась отдельная временная owner-private
папка `dr-app-private-wl2lupmo` в существующей escrow-папке. Автоматический review
отклонил её точное ограниченное удаление (`blocked by policy`); обход не
выполнялся. Она не относится к успешному полному прогону, не является ключом
или неизвестным историческим архивом. Владельцу передан точный путь для очистки.
Факт удаления открытых копий успешного прогона не означает удаления этой папки.

## Что остаётся за пределами доказательства

Это **не восстановление всего нового сервера** после потери VPS и устройства
владельца. Не восстановлены DNS/TLS/Docker networks, внешние SMTP/YooKassa/WB/Ozon
доступы, master/session secrets и независимая вторая копия owner recovery keys.
Реальные вход/оплата/отправка писем и внешние marketplace запросы не выполнялись.

`/app/training-media` — внешний host bind production, отсутствующий в выбранных
control-plane архивах и gateway image. В кандидате страница `/training` отвечает
200, но видео-тегов **0**. Это не доказывает потерю файлов или отсутствие иных
источников уроков; их восстановление после потери host отдельно не проверено.
Также не восстанавливаются внешние host operator scripts. Рабочие уроки на
production этой проверкой не изменены.

Время 99 с — полная репетиция этих данных/образов на действующем сервере,
а не обещанный RTO после потери всей инфраструктуры. `marketing`, `letoocean`
и `alexdalex-msk` имеют прежнюю проверку целостности S3-данных; их приложение
в этой конкретной репетиции не запускалось.

Команда создаёт только свои временные копии/кандидаты. Перед запуском должны
существовать действующие escrow-файлы, rclone remote и Docker images. Нельзя
подменять отсутствующий ledger пустой новой базой. Несовпадение восстановленного
union с текущим live ledger блокирует проверку. `--groups demo` допустим для
узкого preflight; его успешный результат не заменяет полный трёхгрупповой акт.

ограничение cleanup, чужие контейнеры и label mismatch, запрещённые группы,
