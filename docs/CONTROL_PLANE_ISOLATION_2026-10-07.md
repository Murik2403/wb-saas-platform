# P1 control-plane source contract

The production compose configuration separates three internal networks:

- `control_api_net`: gateway and provisioner only. Provisioner has the `provisioner` DNS alias.
- `docker_control_net`: provisioner and writable Docker socket proxy only. No gateway, Traefik or tenant attaches here.
- `docker_discovery_net`: Traefik and the separate read-only Docker discovery proxy only. Discovery `POST=0`; the writable proxy has `POST=1` and is not on the edge network.

Root deployment must create the new networks, replace socket proxies, move gateway/provisioner and update Traefik through the existing host `traefik_up.sh` procedure, retaining every tenant network attachment. A generic compose Traefik replacement can drop those attachments. Runtime network migration is not proven by source tests. The read-only discovery service can still inspect Docker metadata/environment required by discovery; it remains a trusted private Traefik boundary, not a confidentiality filter.

`WB_SAAS_PROVISIONER_BEARER_KEY` is required by compose, present only in gateway/provisioner and never included in tenant environment payloads. Root derives it via `internal_auth.provisioner_credential(gateway_master)` with a distinct HMAC purpose. Every `/v1/*` provisioner request requires the exact Bearer credential using constant-time comparison; missing configuration rejects requests503. `/healthz` remains readable for local readiness. Gateway lifecycle/export, backup scripts, demo reseed and credential-check callers send authenticated headers. Bootstrap ordering: configure the derived key on both services before enabling new server middleware; preserve private networks throughout migration.

Retained encryption keyrings use explicit tenant namespaces: `{"slug":{"old-key-id":"canonical-Fernet-key"}}`. `provisioning.tenant_keyring_for_slug(slug)` returns only that slug's flat ring. Nonempty global flat rings are rejected; they must be explicitly mapped by the operator to the matching tenant without changing key values/IDs. Master and other tenants' retained keys never enter a tenant payload. The release key-derivation helper uses this same scoped function. Tests decrypt a retained ciphertext with the exact selected old key, proving no key-format migration or regeneration is required.

Frontend staging binds only127.0.0.1 and runs UID10001 with a read-only root, dropped capabilities and dedicated writable nginx tmpfs. This is source hardening; root owns runtime staging acceptance and image pins.

## Read-only production inspection and operator sequence

Inspected 2026-10-07 before P1 migration. Gateway currently attaches to `wbsaas_net` and `wb-saas_provisioning_net`; provisioner and the writable socket proxy share the latter. Provisioner retains the `provisioner` alias. Traefik currently mounts `/var/run/docker.sock` read-only and its host static config still uses `unix:///var/run/docker.sock`. A read-only socket mount does **not** make the Docker API read-only. Traefik additionally attaches to all three tenant networks: `wbsaas-tenant-demo`, `wbsaas-tenant-mvvorokov`, and `wbsaas-tenant-marketing`. The two active target deployments must not drop the third tenant's routing.

The current host compose override pins gateway/provisioner images and retains `/app/training-media`; it does not override networks. Preserve that media bind and image pins when publishing the committed compose file. Do not print the full rendered compose config or container environment: these contain secrets.

1. Capture private rollback copies of host compose, override, static/dynamic Traefik configuration and current container network attachments. Keep existing rollback containers stopped: an old proxy connected to a legacy shared network would retain writable Docker reachability even after migration.
2. Publish the committed compose network topology and image pins, preserving the live training-media mount, gateway data volume, provisioner `/backups`, TLS certificates volume and current ACME settings. Configure the derived provisioner Bearer purpose key privately on both gateway and provisioner before starting the protected provisioner. Validate rendered config through a script that emits only service network names, aliases, socket mount presence, ports and allowlisted proxy flags.
3. Create the new internal networks with the committed Compose project (`wb-saas`) and start the separate discovery proxy before touching Traefik. Start/recreate the writable proxy on **only** `docker_control_net`; it may keep the old service DNS name `docker-socket-proxy`. Start/recreate provisioner on `control_api_net` + `docker_control_net`, explicitly preserving alias `provisioner`. Verify local health and an authenticated read-only `/v1` operation without printing its credentials. Then start/recreate gateway on the edge + `control_api_net`, preserving alias `gateway` on both. Verify its authenticated provisioner request succeeds before removing the old shared attachments.
4. Update the **host-mounted** `/opt/wb-saas/traefik/traefik.yml` Docker provider endpoint to `tcp://docker-discovery-proxy:2375`, preserving every other live setting; the committed source has this value, but the running host file did not. Traefik must retain `providers.docker.network: wbsaas_net` and its edge network for ForwardAuth `http://gateway:8000/auth/verify`. Preserve the dynamic middleware and its signed identity response headers.
5. Recreate Traefik only through `/opt/wb-saas/scripts/traefik_up.sh`, using the intended compose/override files in `/opt/wb-saas`. The committed Traefik service removes the raw socket mount and joins `docker_discovery_net` + edge; the script reconnects **all** `wbsaas-tenant-*` networks. Do not use a plain compose Traefik replacement as the final operation.
6. Treat the helper as an action, not proof: its compose/connect pipelines use `|| true`, and it prints `connected` even after a failed connection. Independently compare before/after tenant network sets; require Traefik running, no raw Docker socket mount, endpoint TCP discovery and successful discovery API. Inspect all actual service network memberships and aliases; Compose configuration alone does not prove the running containers changed.
7. Safe permission acceptance: discovery `GET /_ping`/version/containers succeeds as configured; a mutation-method request to a **nonexistent synthetic container ID** is rejected 403 by the discovery proxy (never target a real container). Gateway and tenants must share no network with either socket proxy; Traefik must share none with writable proxy/provisioner control networks. Provisioner alone reaches the writable proxy. Verify apex, `/training`, demo health and authenticated mvvorokov read-only page, plus retained marketing routing. Do not send a real Docker mutation as a security test.
8. Only after the complete acceptance succeeds, disconnect obsolete legacy shared provisioning attachments from surviving active containers. Remove the old network only if empty, with rollback metadata retained. No Docker image pruning, volume removal or backup deletion is part of network migration.

Migration outage window: writable proxy/provisioner replacements briefly stop lifecycle operations; gateway replacement briefly affects ForwardAuth; Traefik replacement briefly affects public routing. A staged pre-attachment approach can shorten this, but must not leave legacy shared writable-proxy access as the final state. A failed migration rolls back the matching compose/config/container network set, not just the image. This inspection made no production mutations and proves topology only, not completed isolation.
