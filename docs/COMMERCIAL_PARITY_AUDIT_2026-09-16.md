# Аудит коммерческой готовности: Streamlit → новый dashboard

Дата: 16.09.2026

## Исправлено в этом срезе

- Добавлен `GET /api/v1/dashboard/finance`: новый интерфейс получает тот же финансовый результат, что и старый экран, включая статьи WB, себестоимость, рекламу и горизонт отчёта.
- Добавлен `POST /api/v1/sync/finance` с периодом 7–365 дней. Это отдельное обновление отчёта реализации WB, без запуска полного импорта.
- В разделе «Финансы» появился список статей расходов и индикатор полноты финансового периода.
- В «Настройки → Синхронизация и журнал» появилась кнопка обновления финансового отчёта WB за 90 дней.
- Добавлены FBS-поставки, новые сборочные задания и коэффициенты приёмки через актуальные Marketplace/Common API WB.
- Добавлен отдельный API-контур удержаний и штрафов за габариты (`/api/v1/dashboard/finance/wb-costs`).

## Фактическое покрытие WB API сейчас

Текущий `tenant-app/wb_api.py` реализует: заказы, продажи, остатки, карточки, FBW-поставки, рекламные кампании/статистику и детализацию отчёта реализации.

Для коммерческого уровня остаются отдельные контуры:

### P0 — деньги и контроль

1. Финансовый баланс продавца и сумма «к выводу» — подключено.
2. Новые финансовые отчёты и детализации по ID; сейчас используется старый `reportDetailByPeriod`, который WB помечает устаревающим.
3. Полный экспорт финансовой сверки в XLSX/PDF из нового интерфейса.
4. Отчёт о свежести данных и повторяемые фоновые попытки при ошибках WB.

### P1 — управление ассортиментом и маржой

1. Цены, скидки и статусы загрузок цен.
2. Тарифы доставки/возврата и коэффициенты приёмки.
3. Платное хранение, операции при приёмке, удержания и отчёты товаров.
4. История остатков и расширенная воронка продаж.

### P1 — операционный контур

1. FBS-сборочные задания, поставки, QR-коды и статусы.
2. Возвраты, вопросы и отзывы покупателей.
3. Управление карточками и медиа из dashboard.
4. Отдельные склады продавца и остатки FBS.

### Ограничения WB API

Некоторые сведения ЛК не выдаются через API (например, часть текущих опций тарифного конструктора). Это нужно явно отмечать в интерфейсе, а не показывать нули.

## План выхода на коммерческий уровень

1. Завершить P0: финансовый XLSX/PDF-экспорт, баланс, новый endpoint отчётов реализации, мониторинг ошибок и свежести.
2. Реализовать P1 по бизнес-ценности: тарифы/хранение → FBS → цены и скидки → аналитика и отзывы.
3. Для каждого tenant включить отдельный токен, журнал синхронизации, backoff/retry, лимиты WB API и проверку отсутствия межtenant-данных.
4. Перед релизом пройти автоматические тесты, clean-clone сборку, Docker smoke и ручной сценарий на тестовом tenant.
