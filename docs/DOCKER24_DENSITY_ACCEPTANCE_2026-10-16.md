## Найденные дефекты PDF

1. **Фоновая очередь не укладывается в объявленный срок при постоянных запросных PDF.** Через HTTP успешно построено 29 / 25 / 13 PDF, тогда как фоновые задания долго остаются queued с attempts=0. Слотов одновременно не более двух. Вероятная причина несправедливого захвата: resident worker пробует `try_pdf_slot` раз в 5 с, HTTP ждёт с опросом каждые 0.5–0.75 с. Нужна гарантия ограниченного ожидания очереди, а не ослабление гейтов.
2. **На 30 кабинетах один запросный PDF получил HTTP 504 за 60047 мс.** Это дополнительный FAIL, не ошибка дашборда. Точный raw: tenant `bench-load-t23-f78610cc`, `api_pdf` record status=504, retry_after=null. Роут `/api/v1/operations/reports/pdf?days=30` идёт через основной nginx `/api/` с default 60 с. Исправление и повторная приёмка ещё не выполнены.

Запросные PDF: 20 — 399 запросов (29×200, 370×503+Retry-After); 25 — 639 (25×200, 614×503); 30 — 889 (13×200, 875×503, 1×504).
