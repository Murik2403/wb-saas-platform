# Исправления после аудита

## Локально внедрено и проверено

- Внутренние credentials gateway привязаны к slug через HMAC-SHA256. Общий мастер-ключ больше не передаётся при создании контейнера. Проверка запрещает ключ A для клиента B и не принимает мастер-ключ как клиентский token.
- Обновление контейнеров теперь действительно использует переданный `--image`; ранее выбранный image скачивался, но запускался конфигурационный default.
- Новый API проверяет Origin для операций записи. Проверено в работающем приложении: внешний Origin → 403; допустимый локальный Origin с пустыми данными → ожидаемый 422, без записи.
- Дополнительно проверяется Host (защита локального API от DNS rebinding): чужой Host → 400. Provisioning и compose передают точный разрешённый домен; nginx сохраняет исходную схему HTTPS от Traefik для корректной проверки Origin.
- Восстановление блокируется, пока работают поддерживаемые API/Streamlit/планировщики. После остановки используется SQLite backup API без удаления WAL/SHM; настройки проверяются заранее, ошибка записи настроек откатывает базу. Safety backup сохраняется. Тесты: открытое WAL-соединение, невалидные настройки, ошибка записи, активный сервис. Произвольные сторонние редакторы SQLite не входят в управление сервисами — перед восстановлением их также нужно закрыть.
- Локальный планировщик принадлежит API и защищён отдельной блокировкой ОС. Импорт и рекомендации запускаются по интервалам; отчёты проверяются раз в минуту; ежедневная резервная копия проверяется раз в час и при запуске. Первая синхронизация после старта ожидает настроенный интервал. Локальные отчёты сохраняются без отправки; рекомендации не применяются автоматически.
- В настройках появились состояние фоновых задач и последние подтверждённые обновления разделов. Даты получены из журнала; старые записи без счётчиков не считаются доказательством свежести.
- Кнопка «Повторить только рекламу» использует отдельный импорт. Проверена в браузере на рабочем кабинете: запуск #23 завершился успешно, 999 строк рекламы, 175 кампаний. Другие разделы этот маршрут не импортирует. Успешный повтор снимает только рекламную причину частичного обновления; финансовые/FIFO ошибки не маскирует.
- Проверка себестоимости теперь обнаруживает частичное покрытие каталога. Значения пользователю не подставлялись: исходные затраты должны быть внесены по фактическим данным.
- Общий расчёт контекста кешируется на 20 секунд; экраны получают независимые копии. На текущей базе: первый today — 1227 мс, следующие stock/production/supply — 35/39/39 мс. Это последовательное локальное измерение, не нагрузочный тест.
- Startup API переведён на lifespan. Три предупреждения ESLint об unused types устранены.
- Скрипты запуска проверяют identity сервиса; добавлен stop-local.ps1. Снимки проверенных Python-пакетов сохранены в `tenant-app/constraints-windows.txt` и `gateway/constraints-windows.txt`. Это Windows-снимки, не Linux lock-файлы.

## Запуск и восстановление на Windows

Основной поддерживаемый локальный интерфейс: `start-local.ps1` → Vite + новый tenant API + локальный планировщик. Next, Streamlit и bridge остаются совместимыми исходниками переходного периода, но для обычной работы не запускаются одновременно с этим путём.

Остановить: `./stop-local.ps1`. Если идёт импорт, скрипт попросит дождаться его; `-Force` предназначен для осознанного прерывания.

Восстановить после остановки всех интерфейсов и сторонних редакторов базы:

```powershell
./tenant-app/.venv/Scripts/python.exe scripts/restore_local.py 'C:\path\backup.zip'
./start-local.ps1
```

Фактическое восстановление рабочей базы не выполнялось. Для нового Windows-окружения установку выполнять с соответствующим `-c constraints-windows.txt -r requirements.txt`; для другой платформы нужен свой проверенный lock.

## Обязательная серверная миграция credentials

Одного обновления gateway недостаточно: существующие контейнеры знают прежний общий ключ и могли бы вычислить производные credentials, если оставить тот же мастер-ключ.

1. Назначить окно обслуживания внутренних доставок и сохранить резервные копии.
2. Сгенерировать **новый** криптографически случайный `WB_SAAS_INTERNAL_API_SECRET` в защищённом окружении gateway. Не помещать его в git/логи/чат.
3. Обновить gateway с новым master и новыми проверками. Старые клиентские credentials после этого намеренно получают 403.
4. Пересоздать клиентские контейнеры через обновлённый provisioning/`scripts/upgrade_all_tenants.py`, сохранив их тома. Каждый получает только scoped credential. Не оставлять fallback, принимающий старый общий ключ.
5. Проверить для каждого клиента внутренний GET статуса Telegram; проверить, что чужой slug получает 403. Это не отправка сообщений.
   Для проверки конфигурации контейнеров подготовлен `scripts/check_tenant_credentials.py`: он только читает состояние и выводит OK/MIGRATION REQUIRED, без ключей и окружения.
6. Удалить старый мастер из окружений и хранилищ развёртывания согласно принятому процессу ротации.

Этот серверный rollout здесь не выполнялся: Docker и подключённый сервер отсутствуют. Защита старых развёрнутых контейнеров не считается включённой до ротации и пересоздания. Docker/Traefik, Linux-блокировки и PostgreSQL требуют отдельной проверки в целевой среде; локальные тесты не заменяют её.
