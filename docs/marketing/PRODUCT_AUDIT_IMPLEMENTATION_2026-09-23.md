## Правила учета и границы

- Выпуск сохраняет стоимость сырья FIFO, труда, упаковки, прочих затрат и износа оборудования. Недостаток любого компонента откатывает всю проводку. Повтор с тем же кодом не дублирует выпуск.
- При отсутствии фактической работы применяется расценка операции из BOM с признаком `bom_norm`. Амортизация — норма ресурса × выпуск, с ограничением общей амортизируемой стоимости. Это не телеметрия оборудования и не расчет зарплатных налогов.
- Отмена восстанавливает сырье и ресурс; использованную готовую партию отменить нельзя. История отмены сохраняется. Новый исправленный выпуск требует нового кода.
- Стоимость выпуска не списывается сразу в прибыль: непроданные изделия остаются запасом. Основной финансовый отчёт использует подтверждённую историческую FIFO-себестоимость по дате финансовой операции WB; несопоставленные строки оцениваются по текущей ставке товара, а при отсутствии положительной ставки отмечаются как непокрытые. В интерфейсе и выгрузках отдельно показаны точные, оценочные и непокрытые единицы; неполная стоимость делает результат предварительным.
- Реализована первая фаза рекомендации BOM: несколько компонентов и версии на SKU (`nm_id`). Отдельная размерная матрица внутри одного `nm_id`, многоуровневые полуфабрикаты и закрытие финансовых периодов не реализованы и не заявляются.
- Календарь отображает сохраненные задания, а не автоматически оптимизирует расписание.
- Производственные роли ограничивают изменения; чтение данных кабинета общее, что прямо указано при приглашении. API-ключ ограничен отдельными маршрутами чтения и одним кабинетом.
- По указанию владельца сравнения/ссылки на 1С не возвращаются. Непроверенные рыночные утверждения из аудита не публикуются. Исключенные самим аудитом внешняя аналитика, РРЦ, антиконтрафакт и расширение браузера не добавлялись.

## Продолжение: FIFO-сверка в React-кабинете — 24.09.2026

- В React-раздел «Финансы» добавлена отдельная FIFO-сверка по дате продажи/возврата и строгая сверка по дате финансовой операции. Последняя использует проверенные строки в основном P&L и отображает оценки по текущей ставке отдельно. Вкладка по дате продажи остаётся диагностической и не подменяет финансовый период WB.
- Источник: `read_sales_fifo_cogs`; API передает период с явным `fifo_cogs_period_basis=sale_date`. На экране указано, что начальные остатки и временные слои могут иметь базовую ставку, поэтому итог не всегда является фактической себестоимостью производства.
- На production-данных Read-only сверка показала 9007 из 9008 финансовых строк «Продажа» и все 321 строки «Возврат», сопоставленные по `nm_id + srid` с локальными продажами. При этом FIFO-слои для обработанных продаж в основном опираются на начальные остатки; выявлены также временные синтетические слои. Это достаточное основание для отдельной сверки, но не для автоматической замены COGS в P&L.

## Следующие функции продукта

1. Размер/цвет в BOM — требует провести `chrt_id` сквозь выпуск, партию готового товара, продажу, возврат и FIFO. Одного выбора размера в форме состава недостаточно.
2. Многоуровневые полуфабрикаты — отдельный FIFO-учёт промежуточных партий, неизменяемый снимок вложенной спецификации и обратная отмена родительских выпусков до дочерних. Существующая текстильная модель НЗП не заменяет такой контур.

## Закрытие FIFO P&L — 24.09.2026

- Основной P&L и прибыль по SKU теперь используют единую построчную проекцию `rrd_id` из финансового отчёта WB и строгой FIFO-сверки по `operation_date`.
- Полностью подтверждённые строки считают фактическую сумму распределённых FIFO-слоёв; продажи и возвраты сохраняют знак операции. Несопоставленная строка целиком оценивается по положительной текущей ставке, частичная FIFO-сумма не смешивается с fallback.
- Строка без подтверждённой FIFO-себестоимости и без положительной ставки остаётся в данных с нулевым числовым вкладом, но помечается как непокрытая; UI явно называет прибыль предварительной. Старую формулу положительный net units × текущая ставка удалили из финансового P&L и расчёта прямой прибыли SKU.
- В API, детализации, CSV/XLSX отражаются точные FIFO-суммы, оценки, количество непокрытых единиц и покрытие. Эти результаты не смешивают `sale_date` с датой финансовой операции.
- Проверки включают точные многослойные продажи, возвраты в отдельном периоде, смешанные строки одного SKU, duplicate `rrd_id`, отсутствие ставки, не-товарные строки, сохранение `nm_id=0`, отсутствие двойного вычитания и сохранение сумм магазина.
