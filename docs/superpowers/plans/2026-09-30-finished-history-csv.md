# Finished FIFO and historical documents CSV Implementation Plan

**Goal:** перенос подтверждённого владельцем начального остатка готовых партий и связанных исторических финансовых документов через существующий CSV preview → explicit confirm, без повторного физического списания.

**Architecture:** отдельный модуль архивного переноса, использующий тот же атомарный журнал migration_import. Реальный FIFO получает только остаток на дату перехода; архивные продажи/возвраты получают отдельные неизменяемые allocations и ручной источник стоимости. Исторические строки не создают sales/движений/доставки и не становятся WB API verified. Shop0 only: secondary/shared canonical warehouse не подменяется этим переносом.

## Contract before implementation

- `finished_lots`: source_id, nm_id, chrt_id, source_date, cutover_date, location (`ready|inbound|wb`), original_units, remaining_units, unit_cost_rub, remaining_cost_rub, document_proof. До 1000 строк/1MB, IDs JS-safe, целые quantities, Decimal rate до6digits; известный ноль стоимости требует явного proof. Остаток0 допустим для полностью исторической партии. Все партии одного nm/chrt имеют одну дату перехода; импорт не заменяет имеющийся FIFO/производственные события/резервы/карантин/общую mapping. Catalog strictvariant. Для ready/inbound требуется пустой локальный склад; WB snapshot если есть обязан точно совпадать с суммой остатка, stock table не переписывается.
- Opening money is integer cents from Decimal(original×rate); remaining_cost_rub explicitly supplies the physical snapshot amount, bounded by original money. Complete historical simulation must leave exactly these remaining quantities and cents. Layer physical quantity equals remaining, never original sold quantity. Proof/actor/time/source snapshots frozen. Cutover means documents before this date, opening exists from this date (source production date retained in archive).
- `historical_documents`: source_id (allocation ID), document_id, rrd_id (actual declared source report row ID), nm_id, chrt_id, operation_date, sequence (explicit unique order within day), event_type (`sale|return`), quantity (whole document), lot_source_id, allocation_units, original_sale_document (`-` for sale), retail_amount, ppvz_for_pay, commission, delivery_rub, storage_fee, deduction, penalty, acceptance, document_proof. Money columns preserve explicit signed original source values: sale retail/payout >=0, return retail/payout <=0, each commission/logistics/storage/deduction/penalty/acceptance sign independent. COGS only receives the operation sign exactly once. Multiple allocation rows same document repeat exactly identical header; total allocation_units==quantity. No overwrite existing financial ID. Each row's catalog variant and lot/date must match. Return references already imported sale and explicit exact lot; returned units never exceed that original allocation; archived cumulative proportional cents retains original residual.
- Historic simulation starts at original gross quantity/money, supports sale10→return5 on original10/remaining5. All historical documents for each involved lot must be present in ONE CSV; chronological sales consume simulated basis and returns restore original allocation residual. Final simulated quantity and cents must EXACTLY equal declared remaining opening. Incomplete histories fail closed. Remaining physical stock never changes on historic import. Opening-only import does not assert prior-history coverage. A post-cutover return linked only to archive remains unresolved, no synthetic stock; an explicit future archive-link bridge is outside this bounded transfer. No synthetic FIFO events. Legacy sales-feed rows older than cutover receive excluded/baseline marker instead of consuming new opening (guard direct process + reconstruction). Financial reader overlays only frozen matching raw financial fingerprint as `manual_source`, money retained, quality preliminary and complete=false across store/product/export.
- Financial source marker uses `legacy_unverified` only. Incoming WB API re-ingestion of an imported rrd may update the actual financial source using existing API semantics; old archived fingerprint then invalidates and downgrades, never duplicate/reapply COGS. Same confirmed source/rrd or duplicate body UUID replays; changed UUID body conflicts. All import journal identities scoped shop0/type/source and append-only replace/update/delete SQL guards.
- Preview read transaction only, no schema creation/data writes; fingerprint includes full catalog, physical snapshot, archive balances, financial/source state and journal. Confirm initializes schema before BEGIN IMMEDIATE, rechecks fingerprint and all rows, then writes whole batch atomically. Actor/role Origin/demo existing middleware retained; explicit selected-secondary deny before work.
- No destructive correction, downgrade after new import requires backup restore preserving later facts; manual historical import cannot claim automatic source verification. Local amounts represent only supplied columns, omitted source schemas not guessed.

## Implemented bounds and release acceptance

Imported lots remain in primary local FIFO. Registering them in the shared warehouse is explicitly rejected: a separate confirmed transfer of monetary basis is required, and this package does not invent it. Partial post-cutover returns whose only source is the historical archive remain unresolved; no physical units are minted. Complete historical file reconciliation is mandatory. Historical/manual cost always remains preliminary.

Exact imported location amounts and valuation use the immutable opening and active allocation cents, within one SQLite read snapshot. Quantities and cents cannot come from different concurrent revisions. Existing non-imported valuation behavior is retained.

Run the isolated helper in the immutable Linux candidate (no production volume/network):
