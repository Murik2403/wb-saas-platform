# Полная DR-репетиция на отдельной ОС

**Цель:** восстановить весь сохранённый контур на новой Ubuntu VM, проверить данные/маршрутизацию, настоящую перезагрузку, фоновые задания и DNS/TLS/ACME без изменения production.

**Архитектура:** новый диск из проверенного подписанного Ubuntu cloud image. Публичный bootstrap только до передачи приватных входов; затем выключение и запуск с блокировкой исходящей TCP/UDP/DNS. Точный набор образов и исходные архивы из owner-only escrow. QEMU TCG проверяется вместо прежнего WHPX, на котором warm reboot не прошёл. Предыдущие диски, архивы и отрицательные акты сохраняются.

**Ограничения:** никаких остановок/изменений/выкладки на production; приватный RSA не покидает Windows; нет отправки реальных писем, Telegram или платёжных запросов; только отдельные тестовые DNS/ACME, рабочая DNS-зона не меняется. Изолированная DNS/ACME-проверка отдельно обозначается и не выдаётся за изменение публичной делегации. Не закрывать пункт при UNKNOWN/FAIL.

## Этапы

- [x] Создать новый owner-only диск, cloud-init с новым SSH-ключом, конечное время работы и проверку принадлежности процесса/портов.
- [x] Подтвердить чистую ОС, установить Docker/host prerequisites без клиентских данных; проверить настоящий warm reboot на TCG.
- [x] Зафиксировать host key, выключить VM, запретить внешний TCP/UDP/DNS, подтвердить ограничения реальными пробами до расшифрованных данных.
- [x] Проверить SHA-256/AEAD/ACL всех исходных копий; загрузить точные образы, восстановить control-plane, пять кабинетов, GlitchTip/PostgreSQL 18 и training-media в новые пустые каталоги.
- [x] Восстановить конфигурацию с минимальными стендовыми заменами: изолированные provider endpoints, backup destinations и ACME authority. Записать все отклонения.
- [ ] Проверить каждую БД, исходные записи/роли/дешифрование, HTTPS/ForwardAuth, SNI, кабинетные API, GlitchTip ingestion, MP4/VTT/Range.
- [x] Проверить host jobs из реальных cron/systemd definitions: backup/offsite/erasure/billing/trial/drift — успешное безопасное исполнение или конкретный FAIL; никаких имитаций PASS по одному --help.
- [x] Проверить shadow DNS и действительный локальный ACME выпуск/обновление плюс восстановленные production TLS certificates; публичную зону не изменять.
- [x] Выполнить reboot целевой ОС, получить новый boot_id и автоматический запуск тех же сервисов, повторить проверки.
- [x] Сохранить акты, выключить только свой стенд, подтвердить сохранность локальных чужих сервисов. Указать незакрытые пункты без переименования FAIL.

## Результат

Выполненная репетиция и reboot приняты для прикладного контура; полная DR-приёмка не закрыта. Незакрытый пункт сквозных API — timeout data-quality у mvvorokov. Остаток по retention/S3, устаревшему drift baseline и host security/agent указан в `docs/DR_NATIVE_REBOOT_ACCEPTANCE_2026-10-16.md`. Отрицательные акты сохранены, runtime-код и production не менялись.
