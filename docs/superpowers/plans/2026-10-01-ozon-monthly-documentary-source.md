# Ozon monthly documentary source — bounded F110 increment

Base: `e9154ae44c12fcc28742408f504805a80e63fffa`; production before this increment was `2d4a8f9`. This implementation adds a separate read-only source acquisition and preview. It does not close the full money ledger or claim a deployment.

## Authority and limits

The freshly read [official monthly realization contract](https://docs.ozon.ru/api/seller/#operation/FinanceAPI_GetRealizationReportV1) supports direct `POST /v1/finance/realization/posting` with month/year. It returns a source header and separate delivery/return commission sections containing integer quantities and numeric totals. The [official report-generation method](https://docs.ozon.ru/api/seller/#operation/CreateCompanyFinanceRealizationPostingReport) is a different external-state creation path and is never called here. The expanded proof is retained outside Git in `audit-private-deliverables-20260930/ozon-official-contract-20261001.json`, SHA256 `db33a7b77a00ccd7d7db98ca4ab7db29c77740ab7be4b16c66a76c52747bda77`.

The report excludes cancellations and non-purchases; Kazakhstan is not supported. Reports are documented back to August 2023. Some monetary component fields are explicitly historical-only before 2024-04-30. The contract does not establish the signed by-day POSTING equation, durable correction identity, or return-to-original-sale linkage required by the documentary movement ledger. No generated CSV, confirmed events, stock movements or FIFO allocations are derived from these observations.

## Implemented acquisition and preview

An owner/manager explicitly loads one chosen nonfuture month, August 2023 or later. `/realization/load` reads the direct source once with a 5-second deadline/request timeout, no retry, no redirects and existing streamed 2 MiB/aggregate 16 MiB guards and 100,000 row cap. The source header must have a scalar document number, valid calendar document date, RUB currency and start/stop dates within the requested year/month. An unsupported header format/period/currency fails closed and leaves the previously saved source intact. Header start/stop are source dates, not an inferred guarantee of full-month coverage.

The immutable envelope contains source kind, requested month/year, complete raw report and request/response hash receipts. Existing `ozon_raw_source_versions` stores it; a separate month-to-source pointer selects the last successful observation. Equal envelopes replay without duplicating raw versions; changed payloads retain both versions. Raw duplicate rows are not discarded. Preview keys are source fingerprint plus occurrence index, **not** stable marketplace operation IDs or correction instructions. This pointer does not replace the daily accounting snapshot or accrue another sum into the daily ledger.

The separate source table shows document number/date, actual source start/stop period, observed line number, SKU, posting reference, and delivery/return quantities and totals independently. A computed partial-period warning distinguishes a source header narrower than the selected calendar month; a matching full calendar header still does not promote completeness. Unknown or malformed values remain unknown; quantities are not negated or interpreted as physical FIFO movements. JSON numeric decimals are read as exact strings; valid RUB totals retain their source sign and kopecks without JavaScript Number conversion. Unsafe money is excluded from that field rather than rounded. Only the first 100 observations are displayed; the complete bounded raw source remains preserved. Payer, recipient, legal-entity and other sensitive details are never returned in preview or rendered.

The current month is labelled provisional. Empty or unavailable reports never imply zero sales/profit. Viewer GET opens saved local data without upstream traffic; owner/manager load respects the existing trusted session, demo/origin and primary-shop boundaries. Secondary WB shops cannot access either new route. All normalization/completeness/confirmation flags stay false and profit is null. No combined monthly-plus-daily financial total is computed.
