# Реализация продуктового аудита 23.09.2026

**Goal:** реализовать замечания PRODUCT_AUDIT_2026-09-23.md в действующем React-кабинете с проверяемым учетом и сохранением существующих данных.
**Architecture:** существующие SQLite/FIFO-модули, изолированные FastAPI routers, React-компоненты производственного учета. Старые одно-материальные операции сохраняют совместимость. Новые версии спецификаций неизменяемы; проводки атомарны и защищены от повторов.
**Stack:** Python/SQLite/FastAPI, React/TypeScript/Vitest.
**Spec:** docs/marketing/PRODUCT_AUDIT_2026-09-23.md, разделы 0, 3–5.

## План и критерии приемки

- [ ] НЗП: production_workspace_api.py + ProductionWorkspace.tsx используют db/wip.py; выдача, завершение, отмена, упаковка, ошибки и остатки проверены.
- [ ] Мощности: чтение/сохранение существующих настроек, календарь с реальными заданиями и перегрузкой.
- [ ] Сырье: единицы из справочника в остатках и нормах, сохранение пользовательского обозначения.
- [ ] CSV: финансовые данные за выбранный период, UTF-8 BOM, защита формул, ссылка рядом с Excel.
- [ ] BOM: несколько материалов, версии, атомарное FIFO-списание при выпуске, откат нехватки одного компонента.
- [ ] Брак: партия сырья, причина, количество, стоимость, повторная отправка не удваивает списание.
- [ ] Сдельная оплата: операции, исполнители, фактическое количество и стоимость в партии выпуска.
- [ ] Оборудование: ресурс и стоимость, амортизация в партии выпуска с прозрачным расчетом.
- [ ] Роли цеха и API интеграций: проработать границы доступа, реализовать отдельным совместимым слоем и проверить запреты.
- [ ] Сохранить исправления Claude в заголовке агентов и отчетах; позиционирование ролей/FIFO только по проверенным возможностям.
- [ ] Проверить мобильные формы, API и регрессии старого выпуска, собрать frontend.
- [ ] Выкладка tenant-образа с резервной копией и проверками бизнес-маршрутов; записать реальные результаты.

## Ограничения исходного аудита

Раздел «осознанно не делать» сохраняется: внешняя аналитика ниш, контроль РРЦ, антиконтрафакт и браузерное расширение не входят в реализацию. Утверждения о закрытии конкурентов и сравнительном превосходстве не являются требованиями к коду и не публикуются. Ссылки и сравнения с 1С не возвращаются по прямому указанию владельца.

## Владение файлами при параллельной работе

Backend производства: db/manufacturing.py, db/core.py, db/production.py и собственные тесты. НЗП/мощности: отдельные production_workspace_api.py и ProductionWorkspace.tsx. Формы затрат: ManufacturingCosts.tsx. Основной агент: интеграция App.tsx/data-source.ts/api_server.py, CSV/единицы, проверка и выпуск. Чужие существующие изменения не откатывать.
