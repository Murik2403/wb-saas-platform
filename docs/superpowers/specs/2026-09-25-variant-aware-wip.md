# Вариантный цикл НЗП: контракт данных

## Цель

Сохранить идентичность товара и варианта Wildberries на всём пути НЗП: выдача сырья → выпуск годных заготовок и брака → упаковка в готовый товар → FIFO-слой готовой продукции.

## Правила

1. Новая партия НЗП обязательно получает `nm_id` и `chrt_id`. `chrt_id=0` означает общий/legacy уровень артикула и допустим только как явно выбранная базовая спецификация. Вариантная партия имеет положительный `chrt_id`.
2. FIFO НЗП списывает только партии с теми же `nm_id`, `chrt_id`, материалом и типом заготовки. Вариант S не может потребить вариант M или старую неразмеченную партию.
3. Старые партии мигрируют с `nm_id=0,chrt_id=0`. Их состав, количество, стоимость, даты, статус и ссылки на движения остаются неизменными. Они остаются видимыми как неразмеченные. Сохранить старое общее потребление можно только для базового товара без вариантов и с `chrt_id=0`; партия никогда не участвует в вариантном FIFO.
4. Новый React-сценарий ручной выдачи в НЗП и ручная комплектация требуют выбора товара и варианта. Выбранная пара проверяется по карточке товара в `products_catalog.raw_json`. Для артикула без вариантов допускается только `chrt_id=0`. Старые Streamlit callers без товарной идентичности сохраняют legacy/base поведение.
5. Задача производства с `chrt_id>0` может закрыть этап НЗП только после полной проверки точного совпадения и доступности партий. Пока проверка не завершена, транзакция ничего не списывает и не оприходует.
6. Повтор того же request/task key с теми же данными возвращает прежний результат без второй проводки. Тот же ключ с другим товаром, вариантом, количеством или датой возвращает конфликт.
7. Отмена выдачи разрешена только до завершения партии. Отмена выпуска заготовок разрешена только до потребления всего выпуска. Отмена упаковки восстанавливает FIFO-allocation в те же WIP-партии; нельзя отменить выпуск сырья/заготовки, если downstream-партия уже использована.
8. Данные `production_cost_batches`, `inventory_movements`, аллокаций и `finished_goods_cost_layers` сохраняют исходные `nm_id/chrt_id`.

## Приёмка

- Миграция populated legacy WIP DB сохраняет все исходные строки/значения и выставляет `0/0` в двух новых полях.
- Две партии с одинаковым материалом/типом, но разным `chrt_id` не смешиваются; недостаток точного варианта даёт ошибку без частичных изменений.
- Путь variant task → WIP issue → completion with scrap → package → ready FG layer сохраняет точный вариант и стоимость FIFO.
- Повторный запрос идемпотентен; повтор того же идентификатора с отличающимся `chrt_id` отклоняется.
- Reversal возвращает единицы только в исходные партии; downstream consumption блокирует отмену.
- Обычная партия `chrt_id=0` сохраняет старое поведение для базового артикула. Неразмеченная legacy партия допустима только в base FIFO (`chrt_id=0`), а cross-variant выдача запрещена.
