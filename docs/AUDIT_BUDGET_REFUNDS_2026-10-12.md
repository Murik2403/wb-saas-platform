# Бюджет кабинетов и пропорциональные возвраты — 12 октября 2026

В общую ветку включены `claude/tenant-budget-20261014` (`85e9517`) и независимые исправления проверки бюджета. Изменения сервера выкладываются из закоммиченного Git archive: gateway, приватный control-proxy, provisioner. Работающие пять кабинетов и их образы не требуется пересоздавать.

## Проверенные изменения

- Общий admission резерв, мягкий лимит нового контейнера и очередь регистрации до 900 секунд. Повтор входа не запускает второй процесс provisioning того же slug.
- Недоступные Docker / RAM / MemAvailable дают повторяемый отказ 503, а не разрешение без проверки. `/v1/capacity` использует согласованную блокировку. `INFO=1` добавлен только приватному управляющему Docker-proxy.
- По выбору владельца успешный частичный возврат сокращает оплаченный срок пропорционально сумме. При оплате сохраняется фактически предоставленный интервал; повтор подтверждения его не переписывает. Расчёт округляет суммарные копейки и секунды, поэтому последовательность малых возвратов не накапливает ошибку.
- Pending не сокращает срок; succeeded применяется однажды; canceled освобождает pending-резерв. Статус и сумма webhook определяются authenticated GET провайдера, а не телом входящего уведомления. Проверяются ID, платёж, RUB, точность суммы и неизменная привязка.
- Административный полный возврат отправляет явный оставшийся размер, а не пустой amount; локальный платёж и уже pending/succeeded суммы проверяются до внешнего действия, сумма ответа провайдера проверяется до записи.
- При двух предоплаченных месяцах половина возврата первого уменьшает общий срок с 60 до 45 дней. Возврат уже использованного старого периода не отнимает отдельно купленную длительность следующего. Для исторического платежа без проверенного интервала частичный срок не угадывается: сохраняется маркер `refund_access_interval_unknown` для сверки.

Полные свежие проверки: **621 gateway passed, 232 subtests; 132 provisioner passed; 2 topology passed**. Новые сценарии сначала воспроизводили ошибки, затем прошли. Реальных списаний, возвратов, регистраций клиентов, внешних сообщений или нагрузочных запусков 20–30 production-кабинетов тесты не выполняли.

Сборка, encrypted backup, candidate/rollback restore, изолированный финансовый smoke и проверка live capacity фиксируются оператором отдельно в `deliveries/tenant-budget-refunds-20261012/deployment-proof.json`. Данный исходный документ сам по себе не подтверждает завершённую выкладку.

## Границы

384 MiB — плановый резерв, а не измеренный пик. Реальное потребление пяти работающих кабинетов проверено read-only: один уже превышает этот резерв. Нагрузочная вместимость 20–30 одновременно активных магазинов, reb​oot/autorestart и общий лимит пиков не доказаны. Ограничения аварийного выключателя и одного процесса перечислены в `TENANT_BUDGET_ROLLOUT_2026-10-14.md`.

Для финансов остаются бухгалтерское подтверждение фискализации/налогов и реальные Ozon-данные. Изменение срока подписки не подтверждает выдачу фискального чека возврата. Долговечная идемпотентность исходящей административной команды при повторном нажатии/потере ответа — отдельная проверка; тесты этого этапа подтверждают идемпотентность применения уже проверенного refund ID.

Обнаружена отдельная задача резервирования: живые tenant SQLite сейчас попадают в tar без online-backup. Сегодняшний полный комплект шести групп успешно восстановлен, но это не доказательство согласованности будущих архивов при конкурентной записи. Подробности в `AUDIT_DISASTER_RECOVERY_2026-10-12.md`.
