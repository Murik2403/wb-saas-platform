## Исправлено при проверке

Локальный запуск использовал старый tenant API через Node bridge, хотя текущие экраны требуют расширенный API из `mh-redesign-lab/tenant-api`. Это давало 404 на инцидентах, производственном исполнении и других операциях. Скрипт запуска теперь выбирает расширенный модуль через `--app-dir`; Vite обращается прямо на порт 8001. Старый bridge исключён из `start-local.ps1`.

После изменения все 22 проверенных GET-запроса вернули HTTP 200; время ответа 0–4,2 секунды в этой проверке. Детали находятся в `mh-redesign-lab/logs/screen-api-audit.json`.

## Найденные проблемы — ещё не исправлены

1. **Индикатор свежести вводит в заблуждение.** На Сегодня/Финансах/Рекламе написано «WB API активно», хотя токен отсутствует и данные устарели. `fetchV1ViewModel` выводит статус из необязательного `sync`, который отсутствует в части ответов. Сегодня возвращает `sync_stale: true`, но этот флаг не используется для индикатора. Требуется единый контракт статуса подключения и свежести.
2. **Карточки рекламных кампаний теряют значения.** API отдаёт 13 кампаний с полями `campaign`, `spend`, `ad_revenue`, `drr`; `adaptCampaigns` ожидает `name/id`, `spend_kop`, `revenue_kop`, `acos_bps`. В результате показываются одинаковые «Кампания» и прочерки. Например, для кампании 34346526 API содержит расход 9 475 руб. и рекламную выручку 138 696 руб. Также заголовок «Нет данных по рекламе» противоречит загруженным KPI. В консоли наблюдались сообщения React о повторяющихся ключах.
3. **Остаток в штуках смешан с отсутствующим прогнозом в днях.** API товаров содержит остатки, но `days_of_stock` равен null при нулевой скорости недавних продаж. В карточке товара показывается «Запас: нет данных», хотя для `cremovple4` есть 66 шт. `_product_inventory` вообще не передаёт количество штук; таблица пишет «остатки WB не загружены», тогда как агрегат склада равен 430 шт. Следует отдельно отображать фактический остаток и невозможность рассчитать покрытие в днях.
4. **Неверный заголовок Отчётов.** `reportMetrics[0].value` — дата резервной копии; UI вставляет её перед текстом «KPI готовы к выгрузке». Нужен показатель количества отчётов/метрик или отдельный заголовок без подстановки даты.
5. **Неполные данные для расчётов.** Последняя успешная синхронизация — 23.08.2026 18:15:54; WB/Ozon не подключены. Таблица `costs` пуста; диагностика показывает покрытие себестоимости 0 из 31 активного товара. Отображаемая расчётная прибыль не подтверждает полноту затрат. Есть диагностическое расхождение WB/FIFO 629 ед.; автоматическая сверка заблокирована кодом и при проверке не запускалась.

## Границы проверки

Проверялось чтение и навигация в настольном браузере. Закупки, платежи, списания, применение рекомендаций, изменение цен, отправка отчётов и запуск синхронизации не выполнялись. Полные сценарии записи, мобильные размеры и внешние интеграции не проверены. Токен не запрашивался и не выводился.

Приоритет следующего шага: исправить контракты отображения и индикатор свежести, затем восстановить подключение WB и заполнить себестоимость по подтверждённым данным.
