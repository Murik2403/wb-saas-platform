Дата: 2026-09-10 · Ветка: `main` · Коммит: `e726870`
Охват: безопасность, готовность к продакшену, качество кода и архитектура.

## 1. Что это за проект

Мультитенантная SaaS-платформа аналитики для продавцов Wildberries (и частично Ozon).

| Компонент | Стек | Роль |
|---|---|---|
| `gateway/` | FastAPI + Jinja2, SQLite/Postgres | Регистрация, логин, сессии, биллинг (ЮKassa), провижининг тенантов, Traefik ForwardAuth, Telegram-релей, админка |
| `tenant-app/` | Streamlit + pandas + matplotlib/reportlab | Дашборд одного тенанта: FIFO-себестоимость, финансы, закупки, производство, остатки, реклама, торговые агенты, PDF-отчёты |
| `traefik/` | Traefik v3.6 | TLS (Let's Encrypt), маршрутизация по поддоменам, forward-auth |
| `frontend/`, `mh-redesign-lab/` | Next.js / Vite | Идущая миграция Streamlit → Next.js (**не в git**, см. P0-2) |

Модель развёртывания: один VPS, один процесс gateway, **по одному Docker-контейнеру на каждого клиента** (изолированный volume + отдельная bridge-сеть). ~35 000 строк Python.

Общее впечатление: **ядро (`gateway/logic/`) написано зрело и с вниманием к безопасности** — чистое разделение бизнес-логики и I/O, продуманные комментарии, хорошее тестовое покрытие gateway. Основные проблемы — **не в коде ядра, а в состоянии репозитория, инфраструктуре развёртывания и цепочке поставки зависимостей.**

## 2. Критично (P0) — чинить в первую очередь

### P0-1. Репозиторий не самодостаточен: deploy из git не соберётся

- `gateway/internal_auth.py` **не в git** (untracked), при этом импортируется в `gateway/provisioning.py` и `gateway/internal_routes.py`. Свежий `git clone` → `ImportError` при старте gateway.
- `gateway/constraints-windows.txt`, `tenant-app/constraints-windows.txt` — тоже не в git.
- Незакоммичен большой рефакторинг (21 файл, +333/−69): scoped per-tenant credentials (`tenant_credential(master, slug)`), правки `sync.py`, `backup_tools.py`, `report_scheduler.py`, `ci.yml` и др.
- Текущая рабочая копия «работает» только потому, что `docker build` делает `COPY . .` и берёт нетрекаемый файл с диска — это **маскирует** проблему: то, что задеплоено, не соответствует тому, что в git.

**Действие:** `git add gateway/internal_auth.py` + все нужные untracked-исходники; закоммитить или явно застэшить in-flight рефакторинг; проверить сборку из чистого клона (`git clone … /tmp/x && cd /tmp/x && docker compose build`).

### P0-2. Рабочая копия и git разошлись катастрофически

`origin/main` содержит только: `gateway/ tenant-app/ traefik/ scripts/ standalone/ docker-compose.yml .github/ DEPLOY.md LAUNCH_GUIDE.md .env.example`.

**Не в git вообще (0 файлов):** `frontend/` (весь Next.js-фронт), `mh-redesign-lab/` (редизайн-лаборатория + `tenant-api/`), `docs/`, `AGENTS.md`, `apex-motors.html`/`del-mar-*.html` (лендинги клиентов), `start-local.ps1`, `task-*.md`, и десятки других файлов на корне.

Риски:
- Потеря рабочей копии = безвозвратная потеря фронтенда и всей документации.
- Непонятно, какая версия фронтенда реально в проде.
- Ревью, история изменений, откат — невозможны для этих кусков.

**Действие:** решить по каждому верхнеуровневому пути — *в git*, *в отдельный репозиторий*, или *в `.gitignore` как мусор*. Довести до состояния «чистый клон = всё, что нужно для сборки и деплоя».

## 3. Высокий приоритет (P1)

### P1-1. Docker-сокет + root: RCE в gateway = root на хосте
`docker-compose.yml` монтирует `/var/run/docker.sock` в gateway **на запись**; оба Dockerfile без `USER` (процесс — root); нет `no-new-privileges`, `cap_drop`, `read_only`.
Любая RCE в gateway (FastAPI, Jinja, зависимость) → полный контроль над Docker API → root на VPS и доступ ко всем тенантским volume.

**Действие:** поставить `tecnativa/docker-socket-proxy` перед gateway с whitelist только нужных эндпоинтов (containers/networks/volumes/images: create/start/stop/inspect); добавить непривилегированного `USER` в оба образа; `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]` где возможно.

### P1-2. CI сломается при коммите текущих изменений
`.github/workflows/ci.yml` (в diff) содержит job `test-frontends` (`working-directory: frontend` → `npm ci`) и шаг `pytest mh-redesign-lab/tenant-api/tests` — обе директории **отсутствуют в git** (P0-2). На чистом checkout эти шаги упадут.

**Действие:** синхронно с P0-2 — либо закоммитить директории, либо убрать соответствующие шаги CI.

### P1-3. Цепочка поставки зависимостей
- `gateway/requirements.txt`: только нижние границы (`fastapi>=0.110`, `uvicorn>=0.29`, `docker>=7.0`, `requests>=2.31`). Это **ровно то, что уже один раз сломало прод** — признано в комментарии `tenant-app/requirements.txt` («fastapi>=0.110 подтянул версию с breaking-изменением `Jinja2Templates.TemplateResponse`»).
- Нет lock-файла (ни `pip-tools`/`uv.lock`, ни hash-pinning) ни в одном из трёх Python-компонентов.
- В CI нет `pip-audit`/`safety`, нет Dependabot/Renovate, нет сканирования Docker-образов (Trivy/Grype).
- `frontend/` и `mh-redesign-lab/` — нет `npm audit` в CI.

**Действие:** проставить верхние границы в `gateway/requirements.txt`; ввести lock-файлы; добавить в CI `pip-audit` и скан образов; включить Dependabot.

### P1-4. API-токены продавцов хранятся в открытом виде
В контейнере `keyring` не имеет бэкенда → `save_token()` пишет `data/.wb_token` **plaintext** (chmod 600), Ozon — `data/.ozon_credentials` plaintext. `backup_tools.py` кладёт весь `data/` в **незашифрованный zip**, а `.env.example` рекомендует синхронизировать `WB_SAAS_BACKUP_DIR` на S3/rclone offsite.
Итог: компрометация одного бэкап-архива = Bearer-токены Wildberries (полный доступ к кабинету продавца, включая рекламу — запись) всех клиентов.

**Действие:** шифровать бэкапы (age/gpg, ключ вне бэкап-хоста) — минимально необходимое; в идеале — шифровать токены at-rest (per-tenant ключ из мастер-секрета gateway, аналогично уже сделанному `tenant_credential`).

## 4. Средний приоритет (P2)

| # | Находка | Детали / действие |
|---|---|---|
| P2-1 | Подделка `X-Forwarded-For` | `gateway/app.py:_client_ip` берёт **первый** элемент XFF. Traefik дописывает реальный IP в конец, поэтому первый — клиентский и подделывается: обход rate-limit (ротацией фейкового IP) и отравление логов/`bind_account_context`. Брать N-й c конца по числу доверенных прокси, либо доверенные IP Traefik. |
| P2-2 | YooKassa webhook без аутентификации | Подписи нет; митигируется ре-верификацией статуса по API (корректно). Но эндпоинт открыт — можно форсить исходящие запросы к API ЮKassa (амплификация). Добавить allowlist IP ЮKassa + rate-limit на `/webhooks/yookassa`. |
| P2-3 | Утечка памяти в RateLimiter | `_history: defaultdict(list)` — пустые ключи после истечения окна не удаляются, один ключ на каждый IP навсегда. Периодически чистить пустые списки или взять TTL-кэш. |
| P2-4 | User-enumeration по времени | `authenticate_account`: при неизвестном email возврат мгновенный (нет PBKDF2), при известном — ~100 мс. Митигируется rate-limit. Добавить прогон dummy-хэша при отсутствии аккаунта. |
| P2-5 | SPOF и in-memory состояние | Один процесс gateway; сессии/rate-limit/CSRF в памяти (рестарт = разлогин всех — задокументировано, но всё же); SQLite control-plane. Задокументировать RTO/RPO; рассмотреть 2-й реплику gateway за Traefik + Postgres + сессии в БД (частично уже готово). |
| P2-6 | Нет бэкапа control-plane БД | Описанный flow бэкапит только тенантские volume. `gateway_data` (аккаунты, платежи, сессии) — вне бэкапа. Добавить в `scripts/backup_*`. |
| P2-7 | Наблюдаемость | Есть структурные логи, нет метрик/алертов/uptime-мониторинга/Sentry. Для платного сервиса «узнать о падении раньше клиента» — обязательно. Минимум: healthcheck-пинг извне + Sentry на оба приложения. |
| P2-8 | Нет ограничения размера загрузки | `internal_routes.py` `await file.read()` целиком в память без лимита размера (эндпоинт за shared-secret, но всё же). Ограничить размер PDF. |

## 5. Низкий приоритет / гигиена (P3)

- **~23 ГБ мусора в рабочей копии:** ~30 файлов `mh-redesign-lab/*.tar` по 763 МБ, 67 файлов `.tmp-*` на корне, директории `.audit2-*`, `.deploy-context-*`, `tmp-pytest-*`, `.production-recommendations-*`, `.verify-*`, `.material-readiness`, `.serena/`, `.codex/`. `.gitignore` покрывает `.audit-*` но не `.audit2-*`, `.deploy-context-*`, `tmp-pytest-*`, `*.tar`. Корневой `.dockerignore` не исключает `*.tar` — build-контекст для `mh-redesign-lab/Dockerfile.tenant-staging` раздувается.
- `.tmp-api-server-remote.py` (79 КБ), `.tmp-calc-remote.py` (46 КБ) на корне — похоже, копии кода с прод-сервера. Убрать или положить осознанно.
- `standalone/config.yaml` содержит **реальный живой WB API-токен** (JWT, exp в 2027) в открытом виде. Файл в `.gitignore` и в историю git не попадал (проверено) — но лежит в рабочей копии plaintext: утечка папки/бэкапа этой машины = утечка токена. Держать в секрет-менеджере или хотя бы вне синхронизируемых директорий.
- Внутри `.deploy-context-*/` и компонентов лежат целые `.venv/` (gitignored) — сотни МБ; удалить.
- Нет `.gitattributes` — git постоянно ругается на CRLF/LF (Windows-разработка, Linux-деплой). Добавить `* text=auto eol=lf`.
- Два параллельных фронтенда (`frontend/` и `mh-redesign-lab/`) — незавершённая миграция, дублирование усилий. Зафиксировать, какой канонический, второй — архивировать.
- `tenant-app/` в git содержит «урезанную» версию; в `.deploy-context-*` — более полная (`api_server.py`, `agents_service.py`, `control_service.py`, `local_jobs.py`, `sync_lock.py`, `today_service.py`…). Неясно, что канон.
- CSRF: на ветках ошибок (`register_submit`/`login_submit`) шаблон повторно рендерится с новым токеном, но `csrf.set_cookie()` на этом Response не вызывается — для пользователя без cookie редкий UX-глюк «форма устарела» дважды подряд.
- `password_issues`: минимум 8 символов, без проверки на утёкшие пароли (HIBP k-anon) и без запрета топ-паролей. Для платного B2B желательно.
- Пароль-хэш: PBKDF2-HMAC-SHA256 260k итераций — приемлемо, но Argon2id предпочтительнее (потребует зависимость).

## 6. Что сделано хорошо (не трогать)

- **Разделение `gateway/logic/` (stdlib + sqlite3, ноль I/O-зависимостей) и тонких HTTP/Docker-обёрток** — образцовая тестируемость.
- Пароли: PBKDF2 260k; в БД только SHA-256-хэши сессионных/reset-токенов; reset-токены одноразовые + TTL; сброс пароля ревокает все сессии.
- CSRF double-submit-cookie поверх `SameSite=Lax`; constant-time сравнение.
- **Мультитенантная сетевая изоляция:** отдельная bridge-сеть на тенанта, tenant-to-tenant трафика физически нет.
- ForwardAuth (`/auth/verify`) проверяет владение **конкретным** слагом — сессия тенанта A не откроет поддомен тенанта B.
- Открытый redirect закрыт (`next` только относительный, не `//`).
- YooKassa: тело вебхука не доверяется, статус ре-верифицируется аутентифицированным API-запросом.
- Zip-slip защита при restore бэкапа (`_validate_zip_names`).
- Allowlist имён таблиц в `db.core.read_table` + регрессионный тест на рассинхрон allowlist ↔ использование.
- 152-ФЗ: серверная (не только HTML `required`) проверка `pdn_consent` + запись timestamp согласия.
- Хорошее покрытие gateway (30+ тест-файлов), CI гоняет реальный Postgres через testcontainers, обе БД-реализации (`?` → `%s`) с общими callers.
- Внимательные комментарии «почему так» — переносимость знаний между разработчиками высокая.
