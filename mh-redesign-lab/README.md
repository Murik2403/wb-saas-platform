# MARKETSHELPER Redesign Lab

## Актуальный локальный запуск

Из корня `wb-saas-platform-clean`:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

Скрипт запускает расширенный `mh-redesign-lab/tenant-api/api_server.py` на порту 8001 с модулями и базой из `tenant-app`, затем Vite на порту 5177. Vite направляет `/tenant-api` прямо на порт 8001. База: `tenant-app/data/wb_dashboard.sqlite3`.

`api:bridge` и цепочка с портом 8011 сохранены для старых staging-развёртываний. Bridge сначала передаёт запросы в актуальный v1 tenant API, а при отсутствии маршрута использует совместимый legacy-адаптер. Для локальной разработки он не нужен: Vite ходит напрямую на порт 8001. Node.js берётся из PATH или установленного runtime Codex; Python — из `tenant-app/.venv`.

Токены из системного хранилища старого компьютера не переносятся вместе с базой. Наличие исторических данных не означает действующее подключение к WB.

Для ввода WB-токена откройте `connect-wb.cmd` из корня проекта. Ввод скрыт; токен сохраняется в хранилище учётных данных Windows. Затем обновите страницу Настройки и запустите синхронизацию. До её успешного завершения приложение продолжит показывать старую дату данных. Команда не проверяет полномочия токена и не запускает импорт автоматически.

При сбое отдельного необязательного этапа (например, рекламы) синхронизация получает статус «частично». Уже загруженные продажи и остатки сохраняются; старая рекламная история не удаляется при ошибке запроса или пустом ответе при существующих кампаниях. Индикатор показывает дату частичного обновления и отсылает к журналу, без заявления о свежести всех данных. Полный статус «успешно» ставится только без ошибок и пропущенных этапов. После запуска из Настроек индикатор обновляется автоматически при завершении.

## Справка по первоначальному прототипу

Отдельная локальная песочница для нового интерфейса. Текущий Streamlit-проект и существующая папка `frontend` не меняются.

```bash
npm install
npm run dev
```

Локальный адрес по умолчанию: `http://127.0.0.1:5177/`.

Прямые ссылки:

- `http://127.0.0.1:5177/?view=today`
- `http://127.0.0.1:5177/?view=stock`
- `http://127.0.0.1:5177/?view=ads`
- `http://127.0.0.1:5177/?view=finance`
- `http://127.0.0.1:5177/?view=production`
- `http://127.0.0.1:5177/?view=supply`
- `http://127.0.0.1:5177/?view=assistant`
- `http://127.0.0.1:5177/?view=reports`

На мобильной ширине нижняя навигация оставляет четыре быстрых раздела, а кнопка меню в верхней панели открывает полный список всех экранов.

Контракты для подключения реального backend API лежат в `docs/api-contracts.md`.

По умолчанию frontend работает в режиме `auto`: пробует tenant API через Vite proxy `/tenant-api`, затем откатывается на локальные mock-данные. Настройки лежат в `.env.example`.

```bash
copy .env.example .env.local
```

Tenant API можно поднять отдельно:

```bash
npm run api:tenant
```

Локальный bridge поднимает будущие `/api/v1/dashboard/...` endpoints поверх текущих legacy `/api/today` и `/api/overview?period=30d`, не меняя код основного проекта:

```bash
npm run api:bridge
```

Dev-цепочка:

- `http://127.0.0.1:8001` — существующий tenant API.
- `http://127.0.0.1:8011` — redesign API bridge.
- `http://127.0.0.1:5177` — новый React frontend.

Режимы:

- `VITE_MH_API_MODE=auto` — пробовать bridge/v1 API, потом legacy `/api/today`, потом mock fallback.
- `VITE_MH_API_MODE=v1` — использовать только `/api/v1/dashboard/...`.
- `VITE_MH_API_MODE=legacy` — использовать только существующий `/api/today`.
- `VITE_MH_API_MODE=mock` — не делать сетевых запросов.

Tenant-образ для staging собирается с `VITE_MH_API_MODE=v1`, поэтому опубликованный интерфейс использует полный tenant API. Режим `legacy` оставлен только для ручной проверки совместимости со старым `/api/today`.

Legacy API может считаться несколько секунд. В это время интерфейс показывает mock-данные с loading-баннером, затем переключается в `WB API активно` или `WB API устарел`, если backend сообщает о stale sync.

Разделы `Финансы`, `Отчеты`, `Склад`, `Реклама` уже используют данные `/api/overview?period=30d` там, где они доступны. `Производство`, `Поставки` и `AI агент` имеют полный UI-каркас и готовы принять отдельные endpoints; пока они частично строятся из текущих today/stock/action данных и fallback-модели.

Быстрая проверка горизонтального overflow:

```bash
npm run qa:layout -- "http://127.0.0.1:5177/?view=today" 390x844
```

Для live-проверки legacy API можно добавить время ожидания:

```bash
npm run qa:layout -- "http://127.0.0.1:5177/?view=today" 390x844 25000
```
