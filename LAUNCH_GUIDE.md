# Запуск MARKETSHELPER в продакшн: пошаговый план

У вас уже есть ИП/ООО, домен пока не выбран, сервер нужно посоветовать.
Ниже — конкретный порядок действий с командами, ссылками и текущими
ценами (проверено веб-поиском в августе 2026, но цены у хостеров меняются
— смотрите актуальные перед оплатой).

**Срочное замечание про домен** — см. Шаг 1, там есть дедлайн, который
касается вас прямо сейчас.

## Порядок действий

1. Домен
2. Сервер (VPS)
3. Первый деплой проекта
4. ЮKassa (получить shopId и ключ)
5. Почта (SMTP) для восстановления пароля
6. Бэкапы во внешнее хранилище
7. Финальный чек-лист перед первым платящим клиентом

## Шаг 1. Домен

### ⚠ Важно и срочно: закон о домене по паспорту

С **1 сентября 2026 года** (по 152-ФЗ/569-ФЗ) администраторы доменов в
зонах **.ru, .рф и .su** обязаны проходить идентификацию через
**Госуслуги** — старые способы подтверждения личности перестают работать.
Это буквально через пару недель от сегодняшнего дня. Если у вас (или у
того, на кого будет оформлен домен) нет подтверждённой учётной записи на
Госуслугах — оформите её заранее, иначе регистрация/продление `.ru`-домена
может застопориться прямо на старте.

Практический вывод: если хотите не связываться с этим прямо сейчас —
берите домен в зоне **.com** (закон её не касается) и возвращайтесь к
`.ru` позже, когда разберётесь с Госуслугами. Технически `.com` работает
для этого проекта абсолютно так же, как `.ru`.

### Как назвать проект

В коде и шаблонах сайта уже зашито название **«MARKETSHELPER»** (заголовки
страниц входа/регистрации). Логично взять домен в тон:

- `wbcontrol.ru` / `wb-control.ru`
- `wbcontrol.com` (если решите не связываться с `.ru` из-за закона выше)
- `getwbcontrol.ru`, `mywbcontrol.ru`
- `wbctrl.ru` (короче)

Проверить свободен ли домен и купить — на любом из регистраторов ниже.

### Где купить

- **REG.RU** — крупнейший российский регистратор. `.ru` от ~169 ₽ за
  первый год (цена продления обычно заметно выше — смотрите её отдельно,
  не только цену при покупке). https://www.reg.ru/domain/new/RU
- **Timeweb** — регистрация домена в той же панели, что и сервер, если
  берёте VPS у них же (Шаг 2) — удобно, всё в одном личном кабинете.

### Настройка DNS (когда домен куплен)

Понадобятся две записи, обе указывают на IP вашего сервера (получите его
на Шаге 2):

```
wbcontrol.ru         A    <IP сервера>
*.app.wbcontrol.ru    A    <IP сервера>     ← wildcard, для поддоменов клиентов
```

Wildcard-запись (`*.app`) — стандартная функция DNS, должна быть в панели
регистратора, но у бюджетных панелей иногда обрезана. Если в веб-интерфейсе
регистратора не получается создать запись с хостом `*`, самый надёжный
вариант — перевести NS-записи домена на **Cloudflare** (бесплатно) и
управлять DNS уже там: там wildcard работает гарантированно.

## Шаг 2. Сервер (VPS)

### Рекомендация: Timeweb Cloud

- Конфигурация для старта: **2 vCPU / 4 GB RAM / 50 GB SSD** — этого
  достаточно на несколько первых клиентов (каждому клиенту — свой
  контейнер, ограниченный по `WB_SAAS_TENANT_MEM_LIMIT`, по умолчанию
  768 MB).
- Цена: около **1080 ₽/мес** (дешевле при оплате на 12 месяцев вперёд).
- Почему: простой Docker на обычной VPS (не «управляемый» сервис — вам
  нужен именно root-доступ и голый Docker, так как шлюз сам поднимает
  контейнеры клиентов через Docker SDK), хорошая репутация, есть API для
  автоматизации, дата-центры в Москве.
- https://timeweb.cloud/services/vds-vps

**Альтернативы**, если Timeweb не подойдёт:
- **Selectel** — более «энтерпрайзный», чуть сложнее интерфейс, хорош если
  дальше собираетесь сильно расти. https://selectel.ru/services/cloud/vps-vds/
- **VDSina** — дешевле (~$20/мес за похожую конфигурацию), NVMe-диски,
  щедрый трафик, но менее известный бренд. https://www.vdsina.ru/pricing

Требования к серверу (любой провайдер): Ubuntu/Debian, root-доступ, порты
80 и 443 открыты наружу (нужны Traefik и Let's Encrypt), Docker + Docker
Compose v2.

### Создание сервера — что сделать в панели провайдера

1. Заказать VPS с Ubuntu 22.04 (или новее).
2. Получить IP-адрес — он пойдёт в DNS-записи (Шаг 1).
3. Подключиться по SSH.
4. Поставить Docker и Docker Compose, если их нет в образе:
   ```bash
   curl -fsSL https://get.docker.com | sh
   apt install docker-compose-plugin -y
   ```

## Шаг 3. Первый деплой проекта

Полная инструкция уже лежит в `DEPLOY.md` внутри архива `WB_SaaS_platform.zip`,
который я вам отправлял — она написана специально под этот момент. Коротко,
что делать на сервере:

```bash
# скопировать проект на сервер (scp/git — как вам удобнее), затем:
cp .env.example .env
nano .env   # заполнить как минимум WB_SAAS_PARENT_DOMAIN и WB_SAAS_ACME_EMAIL

docker build -t wb-dashboard-tenant:latest ./tenant-app
docker compose up -d --build
docker compose logs -f gateway   # смотрите, что всё стартовало без ошибок
```

Дальше — чек-лист из `DEPLOY.md` («Первый запуск»): зарегистрировать
тестовый аккаунт, убедиться что провижининг отработал, что поддомен без
входа кидает на `/login`, что второй клиент не видит данные первого, что
в боковой панели дашборда есть кнопка «💳 Подписка».

Про переменные `WB_SAAS_YOOKASSA_*`, `WB_SAAS_SMTP_*` и `WB_SAAS_BACKUP_*`
в `.env` — заполните их после шагов 4–6 ниже, до тех пор оплата/письма/
бэкапы просто не будут работать, но остальной сайт будет жить.

## Шаг 4. ЮKassa

Раз ИП/ООО уже есть — юридической части почти нет, это просто регистрация
магазина в личном кабинете.

1. Идите на https://yookassa.ru/connection/ → «Подключить ЮKassa».
2. Укажите телефон, имя, email, форму бизнеса и **ИНН**.
3. Заполните данные организации в личном кабинете: реквизиты, скан
   паспорта владельца (и совладельцев, если есть).
4. Отправьте на проверку — по данным ЮKassa занимает обычно пару дней,
   иногда быстрее; если чего-то не хватает, попросят донести через
   личный кабинет/email.
5. Подпишите договор электронно (СМС-код) — визит в офис не нужен.
6. Получите **shopId** и **секретный ключ**: Личный кабинет → Интеграция →
   API-ключи → сгенерировать ключ (подтверждается по SMS).
7. Впишите в `.env`:
   ```
   WB_SAAS_YOOKASSA_SHOP_ID=...
   WB_SAAS_YOOKASSA_SECRET_KEY=...
   ```

### Комиссия

На сайте заявлена ставка «от 0,4%», но для большинства обычных
подключений реальная ставка — около **2,8% + фиксированная часть** за
платёж картой/SberPay/T-Pay и т.п. Пониженные ставки — по индивидальным
условиям при обороте от 5 млн ₽/мес через персонального менеджера.
Уточните точные условия для вашего оборота у менеджера ЮKassa при
подключении — расчётная ставка стоит того, чтобы её знать заранее, она
прямо влияет на то, сколько вы фактически получите с 2990 ₽ подписки.
https://yookassa.ru/fees/

### Тестовый режим

В личном кабинете ЮKassa есть тестовый магазин/тестовый режим для
интеграционных проверок до включения реальных платежей — им обязательно
стоит воспользоваться перед первым реальным клиентом: пройти полный цикл
регистрация → `/billing` → оплата тестовой картой → вебхук → продление
подписки — именно это описано как непроверенное в `DEPLOY.md`, потому что
в среде, где писался код, не было доступа к api.yookassa.ru.

### Вебхук

В личном кабинете ЮKassa → «Настройки» → «HTTP-уведомления»:
```
https://wbcontrol.ru/webhooks/yookassa
```
(замените на ваш домен), включить события `payment.succeeded` и
`payment.canceled`.

### Ежедневный биллинг-цикл

Не забудьте прописать cron из `DEPLOY.md` (списание оплаты за
продлившиеся подписки, перевод просроченных в льготный период) — без
него разовые оплаты будут работать, но продления подписок — нет.

## Шаг 5. Почта (SMTP) для восстановления пароля

### Рекомендация: UniSender Go

- Специально заточен под транзакционные письма (то, что нужно — ссылки
  сброса пароля, а не рассылки).
- Есть бесплатный стартовый лимит, дальше — от ~800 ₽/мес за ~6000
  писем/мес (сильно больше, чем вам понадобится на старте). Оплата в
  рублях, без проблем с иностранными картами.
- https://go.unisender.ru/

### Альтернатива: Яндекс 360 для бизнеса

- Если хотите ещё и настоящий почтовый ящик на домене (`support@wbcontrol.ru`),
  не только транзакционную отправку — от ~319 ₽/мес за пользователя.
- Менее удобен именно как API для отправки писем по расписанию/событию,
  больше подходит как обычная почта.

### Почему не SendGrid/Mailgun

Технически письма долетают, но оплата из России иностранной картой сейчас
— отдельная головная боль (нужна виртуальная карта в валюте или
посредник). Для простой задачи «отправить ссылку сброса пароля» это
лишнее усложнение — берите российский сервис.

### Что вписать в `.env`

После регистрации в выбранном сервисе получите SMTP-хост/логин/пароль и
впишите:
```
WB_SAAS_SMTP_HOST=...
WB_SAAS_SMTP_PORT=587
WB_SAAS_SMTP_USER=...
WB_SAAS_SMTP_PASSWORD=...
WB_SAAS_SMTP_FROM_EMAIL=no-reply@wbcontrol.ru
```
Пока это не заполнено, `/forgot-password` продолжает работать (не
ломается), но письмо реально никуда не уходит — только в лог. Проверьте
это на реальном письме до того, как полагаться на функцию.

## Шаг 6. Бэкапы во внешнее хранилище

Скрипт `scripts/backup_tenant_volumes.py` уже делает локальные бэкапы
Docker-томов каждого клиента на диск сервера (`WB_SAAS_BACKUP_DIR`,
раз в сутки по cron — см. `DEPLOY.md`). Но это тот же самый сервер — при
его полной потере локальные бэкапы пропадут вместе с оригиналом.

Проще всего — настроить `rclone` на выгрузку папки с бэкапами в облачное
хранилище (Яндекс.Диск, S3-совместимое хранилище у Selectel/Timeweb и
т.п.), отдельным cron-заданием раз в сутки после самого бэкапа. Это одна
команда `rclone sync` — оформление зависит от того, какое хранилище
выберете; спросите отдельно, когда дойдёте до этого шага, помогу
настроить под конкретный сервис.

## Шаг 7. Финальный чек-лист перед первым платящим клиентом

- [ ] Домен куплен, DNS настроен (обычная + wildcard запись), сайт
      открывается по HTTPS (Traefik сам получит сертификат Let's Encrypt
      при первом запуске — если не получил, смотрите `docker compose logs
      traefik`).
- [ ] Тестовая регистрация → провижининг → вход на поддомен → выход →
      второй тестовый аккаунт не видит данные первого.
- [ ] ЮKassa подключена, вебхук зарегистрирован, полный цикл оплаты
      пройден в тестовом режиме ЮKassa.
- [ ] Ежедневный биллинг-цикл (`run_billing_cycle.py`) прописан в cron и
      один раз прогнан вручную.
- [ ] SMTP настроен, письмо восстановления пароля реально дошло до
      реального почтового ящика.
- [ ] Хост-бэкап (`backup_tenant_volumes.py`) прописан в cron, один раз
      прогнан вручную, и настроена выгрузка бэкапов во внешнее хранилище.
- [ ] Прочитан раздел «Ограничения текущей версии» в `DEPLOY.md` — там
      честно перечислено, что именно не проверялось вживую в песочнице
      (реальный Streamlit-прогон, happy path отката ретроактивной
      FIFO-реконструкции) и стоит хотя бы разово проверить руками.

Как только всё это отмечено — можно приглашать первого настоящего
клиента.
